## 本阶段发现并解决的引擎/数据问题（治理证据）

1. **wren-core 0.7.6 DECIMAL 规划缺陷（重要）**: MDL 声明 DECIMAL 的列在 CLI 规划器与 wasm 中均退化为 Utf8，
   计算列算术（如晋升幅度）直接失败。处理: 全项目 MDL 数值类型统一 DOUBLE（PG 执行不受影响，parquet 对齐）；
   `promotions.raise_pct` 计算列因 round(double,int) 下推问题改为查询时计算，`contracts.is_expiring_soon`（无算术）保留为计算列。
2. **`wren memory store` 中文 slug 缺陷**: 中文问题生成 slug 时退化为残缺文件名（曾固定写 query.md 互相覆盖），
   Phase 1 的 11 组 NL→SQL 实际从未入库。处理: 41 题全部重新 store（`-q` 参数不支持也曾导致静默失败），
   knowledge/sql/ 现 42 个文件，语义召回验证可命中。
3. **视图内列算术规划失败**（Phase 1 已发现，v2 延续遵守）: 新增 3 视图均为纯关联投影，算术全部在查询/cube 聚合层。

## 2026-09-26 数据层迁移: PostgreSQL → DuckDB（同日移除 PG 版）

- 验证日期: 2026-09-26 · 数据快照不变: 2026-08-31
- **A 路径(标准答案)**: duckdb 只读挂载 `db/duckdb/public.duckdb`，经 `.venv` 内 duckdb 子进程执行
- **B 路径(被测路径)**: 不变，经 wren 语义层；项目 profile 为 hr_demo_duck(duckdb)
- **结果: 41/41 PASS；P0 口径题 11/11 PASS；连续两次全量运行 summary.csv 完全一致（确定性验证）**
- **PG 版去留**: 迁移完成后按项目决定于同日整体移除 PG 数据层（schema.sql/load.sh/gen_attendance.sql
  删除、runner psql 回退移除、hr_demo profile 清理）。本节前半部分描述的迁移过程按发生顺序保留。

### 迁移方案要点

1. **库文件名必须为 `public.duckdb`**: wren 的 duckdb 连接器按文件名为挂载 catalog 别名，
   MDL 规划 SQL 以 `"public"` 前缀限定物理表（`"public".employees`）→ 挂载别名=public 恰好命中。
   25 个模型 YAML 的 table_reference 零改动。
2. **数据同源**: 24 张表直接装载 seed/out、seed/out2 既有 CSV；attendance_records（库内 random()
   生成、无 CSV）取自仪表盘 Parquet 快照（确定性快照，含原始 att_id，203,679 行），
   仪表盘 Parquet 与历史验证数字无需重算。
3. **schema 转换** (`db/schema_duckdb.sql`): SERIAL→INTEGER 主键（装载器生成）；
   不声明 REFERENCES 外键（DuckDB 1.5.5 会即时执行外键校验，employees.manager_id 自引用无法
   单条装载；表间一致性由 CSV 源数据与装载顺序保证，关系定义见 relationships.yml）；
   CHECK/UNIQUE/COMMENT ON 保留。
4. **构建入口**: `db/load_duckdb.sh`（= build_duckdb.py，考勤来源 auto: parquet→SQL 重生成回退），
   不依赖 Docker；`gen_attendance_duckdb.sql` 仅作无快照时的最后回退（随机序列与快照不可比）。

### 本阶段发现并解决的验证问题（治理证据）

4. **q12/q35 无序 LIMIT 缺陷（重要，回溯性修复）**: 两题问题文本为 "Top5"，SQL 却是
   `GROUP BY ... LIMIT 5` 无 ORDER BY。PG 哈希分组输出顺序恰好稳定，历史 PASS 属稳定但不正确：
   q35 的 PG 历史结果包含 工作文化(13人) 而漏掉 管理问题(22人)，Top5 答案一直是错的
   （正确 Top5: 薪酬福利42 / 职业发展42 / 管理问题22 / 健康19 / 家庭个人15）。
   处理: 两题 gt/wren SQL 补 `ORDER BY 计数 DESC`（边界值无并列：q12 6v4、q35 15v13），
   修复后答案与问题语义一致。此缺陷与数据层迁移无关，任何引擎下都应修复。
5. **DuckDB 并行扫描下 `row_number() OVER ()` 不保序**: parquet 读入分配序号会乱序；
   考勤改用 parquet 自带 att_id。CSV 路径实测保序，但新增表时建议显式 ORDER BY。

## 2026-10-05 优化验收

本节记录本轮实际执行，数据快照仍为 **2026-08-31**。当前两条 SQL 路径均访问同一 DuckDB：A 直接查询物理表，B 经 Wren 规划与查询；不是跨数据库验证，也不等同于自然语言生成准确率。历史目录中的结果已由本轮完整回归更新。

### 已修正的定义与数据流

- 删除 `promotions.reason` 下误植的重复 YAML 键，使晋升原因恢复为文本；晋升调薪幅度在查询中计算。模型生成器改为校验/复制规范 YAML，不再用旧模板覆盖修复。
- 年龄、司龄、合同预警统一固定快照日期。年龄仍为年份差；合同预警含快照日至第 90 天，两端闭合，不包含已过期合同。本次 q18 为 **16** 份预警合同、37 份无固定期限履约合同，取代历史运行日期相关数字。
- q16 晋升员工去重，本次为 **48 / 344 = 13.95%**；q40 人均月总成本采用期间发薪人次，最高部门为总经办，展示值 **158,406 元**。历史部门归属仍按当前员工档案，未还原调岗。
- 排名和趋势题增加确定排序及 `ordered` 比较，共 9 题声明顺序要求；相应知识示例同步更新。
- `memory check` 发现旧索引含无源文件的查询记录；备份衍生缓存后 reset/index，检查为 **In sync**，晋升问题召回已命中新去重口径。知识源文件保留。
- 考勤种子迁至 `db/seed/attendance_records.parquet` 并附 SHA-256 清单。标准构库不再反向依赖仪表盘文件，也不在缺失时随机回退；临时库全部成功后才替换目标库。CSV/Parquet 路径改为参数传入，工作区含单引号也可构库；参数化后的全量临时重建仍与现有库逐表一致，证据在 `runs/rebuild-20261005/result.json`。
